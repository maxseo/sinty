# A chat opens with the whole transcript

- Date: 2026-11-02
- Area: apps/web
- Plan step: none
- Commits: this commit
- PR: (open)

## What and why

Refreshing the harness, or switching to a chat, painted the journal one event at a time and kept the view pinned to the bottom. The person saw their last request, then each supervisor note, and only afterwards the agent's reply, as if the turn were running again. The same path is used for every chat, so a long one made it obvious and the shorter ones did it too.

The page now reads `/v1/sessions/:id/events` until the journal is in hand and draws that list once. The event stream starts after the last sequence it already has, so a new message still arrives live.

Checked in the browser: «Видео» (1987 events) and «Тест 8» (14920 events). The first and last message appeared in the same paint. The text length jumped from the empty shell to the full transcript in one step.

## Files touched

- `apps/web/src/chat.tsx` — history in one draw, stream only for what follows

## Design decisions

The stream still carries live events. Only the catch-up of an already written journal is a single request.

## Rejected alternatives

Hiding the log until the stream finished. The stream would still walk every old event, and a chat of fifteen thousand events would stay blank for the whole replay.

## Migration notes

Refresh the harness once so the page loads the new script.

## Known limitations

A chat still draws every message it has. A very long one is one large paint, not a replay.
