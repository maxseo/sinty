# Site chat

A visitor can talk to the agent before the site has a domain.

## What changed

`/p/site/chat` keeps a thread in the site database and a matching harness session. The cookie `site_chat` is the thread id. Each message runs one turn on channel `web` and stores the visitor text and the answer. The Чаты tab and `site.chats` list the threads. The plugin manifest now has `sessions.read` and `sessions.write`, which is what lets the public page open a session.

## Why

The agreed plan puts chat after pages and forms, and before the VPS. The reply is a normal harness turn, so the same agent that edits the site can answer, and a blocked turn still shows up in the harness.

## Test

`plugins/site/src/store.test.ts` stores a visitor line and an agent line on one thread. The page itself was not driven through a model.
