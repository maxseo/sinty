# The open editor recompiles when the agent writes the film

- Date: 2026-11-02
- Area: plugins/diffusion, vendor/diffusion-editor
- Plan step: none
- Commits: this commit
- PR: (open)

## What and why

In the chat «Видео» the agent rewrote `index.tsx` into two clips. The file on disk was the new cut. The pane beside the chat stayed on the old one until the page was refreshed. `check` also alternated between the old scene (one shape, 18.033 s, playhead at 7.67 s) and the new one (two videos, 15.033 s, playhead at 0). Two editors were answering one queue, and neither was told to reload in the form it listens for.

`noteChange` pushed `projects:changed` on its own. The editor only listens on `main:event`, and then reads the channel inside that envelope. The reload never started. A refresh compiled the file from disk, which is why the new cut appeared only then.

The note is now a `main:event` for `projects:changed`, with the path relative to the film folder. It is not removed by the first editor that polls: each copy asks with `since` and receives anything it has not seen. An old page that does not send `since` still gets the note for a second and a half, then stops, so it does not reload forever.

## Files touched

- `plugins/diffusion/src/host.ts` — the note and `takeInbox(since)`
- `plugins/diffusion/src/index.ts` — the inbox reads `since`
- `vendor/diffusion-editor/apps/web/public/harness-desktop.js` — remembers the last note
- `vendor/diffusion-editor/apps/web/index.html` — `harness-desktop.js?v=5`
- `skills/diffusion-editor/SKILL.md` — do not ask for a refresh; a check in the same second can still see the previous cut

## Design decisions

Tool calls stay a single queue. The reload does not, because the pane the person is looking at has to move even when another copy answers a command.

## Rejected alternatives

Asking the person to refresh after every edit. That is what already happened, and the cut was invisible while the agent was working.

## Migration notes

Ctrl+F5 once, so the page loads `harness-desktop.js?v=5`. After that, `diffusion.source` write updates the open film by itself.

## Known limitations

A `check` that lands while the recompile is still running can describe the previous cut. The picture catches up when the compile finishes.
