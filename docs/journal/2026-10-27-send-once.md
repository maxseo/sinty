# One send, one turn

## What changed

`apps/web/src/chat.tsx`. The composer keeps one idempotency key for the current text, agent and attachments until the server accepts it. A ref blocks a second submit before React disables the button. A failed request retries with the same key.

## Why

The API already returns the first turn when `idempotency-key` repeats. The button minted a new key on every click, so a double-click opened two turns.

## Revert

Restore `crypto.randomUUID()` on each submit and drop `sendGuard` / `pendingSend`.
