# Memory step 0: retire plugins/memory, reserve core tool names, fix scopes, one connection

- Date: 2026-10-19
- Area: packages/core (memory, agent, host), plugins, registry
- Plan step: memory plan, step 0 ("hygiene before the contract")
- Commits: golden baseline `test(core): golden-prompt baseline…`, then `feat(core): memory step 0…`
- PR: [#1](https://github.com/maxseo/sinty/pull/1) (merge `bb47710`)

## What and why

1. **Golden baseline first.** Before touching memory code, `packages/core/src/__tests__/golden.test.ts`
   recorded exactly what the model receives (system prompt, skills block, memory block, summary block, dialogue,
   tool list) in three flows: memory tools across sessions, recall, and compaction with a summary call.
   Snapshots live in `packages/core/src/__tests__/golden/*.json` and were captured on main `6bc1396`.
   Every later memory step must keep them byte-for-byte equal in the default configuration.
2. **`plugins/memory` removed.** It duplicated the core memory (`memory.recall/write/forget` are core tools in
   `coretools.ts`), so when enabled it was silently shadowed: `Agent.allTools()` drops plugin tools with core
   names. Two implementations of the same tool names with different storage was a trap. It is deleted, dropped
   from `registry/plugins.json` (regenerated by `scripts/registry.mjs`) and from `pnpm-lock.yaml`.
3. **Reserved core tool names.** `PluginProcess.start()` now fails a plugin whose `ready` message lists a tool
   whose name is in `CORE_TOOL_NAMES`, with the error `tool name X is reserved by the core`. `PluginHost.start()`
   also logs a warning when two plugins register the same tool name (the first one keeps winning in
   `toolOwner()`, as before).
4. **Scopes in `profile()` / `recentLog()`.** They used to filter only by `user_id`, so agent-scoped and
   chat-scoped facts of *any* persona or chat leaked into every prompt. Both now use the same visibility rule as
   `recall()`: user-wide facts, plus agent facts of the asking persona, plus chat facts of this chat.
5. **Persona id as agentId.** `MemoryStore` takes `agentId` per call (`write`, `recall`, `profile`,
   `recentLog`). The agent passes the roster persona that speaks in the session (`speaker(sessionId).id`) and
   falls back to `config.agent.name` outside projects. Before, every persona shared `config.agent.name`.
6. **One long-lived connection.** The agent used to open and close `memory.db` (and load sqlite-vec) on every
   context build and every memory tool call. Now one `MemoryStore` stays open and is closed in `Agent.stop()`
   (step 2 moves ownership to `MemoryRouter`).
7. **Compaction facts are journaled.** Facts extracted by the summary call are written with
   `source: "summary"` and now also produce a `memory.written` journal event
   (`{ id, action, tier, scope, source, provider: "builtin" }`), so the journal stays the record of what entered
   memory and why. Tool writes are not duplicated as `memory.written`; their `tool.call.completed` event already
   carries the result.

## Files touched

- `packages/core/src/memory.ts` — `MemoryWho`, per-call `agentId`, scoped `profile()`/`recentLog()`, `all()`,
  `database`/`dimensions` getters, idempotent `close()`.
- `packages/core/src/agent.ts` — `memoryAgentId()`, long-lived `openMemory()`, `memory.written` on summary facts.
- `packages/core/src/host/host.ts` — reserved names, duplicate warning.
- `packages/sdk/src/events.ts` — `memory.written` event type.
- `plugins/memory/**` deleted; `registry/plugins.json`, `pnpm-lock.yaml` regenerated.
- Tests: `golden.test.ts` + `golden/*.json`, `reserved.test.ts`, new case in `memory.test.ts`,
  fixtures `test-fixtures/plugins/recording-provider` and `shadow-core`.
- `harness.test.ts` — the two Windows-only shell sandbox tests are skipped off Windows (TODO kept in the file).

## Design decisions

- Reject instead of warn for reserved names: a plugin that ships `memory.write` would otherwise look healthy
  while never being called. Failing start puts the reason in `failedPlugins` and in the log.
- Visibility for the profile block reuses `visible()` so the prompt block, recall and the scope semantics
  documented in `coretools.ts` can no longer drift apart.
- `agentId` per call rather than one store per persona: one connection, one WAL, no cache of stores to evict.

## Rejected alternatives

- Keeping `plugins/memory` as "deprecated": it could never run (shadowed), so a deprecation period had no users.
- Making plugin tools override core tools: breaks the "protected core" rule in `docs/architecture.md`.
- Migrating old `agent_id = config.agent.name` rows to persona ids: we cannot know which persona wrote them.

## Migration notes

- Existing `memory.db` files work unchanged; no schema change.
- Agent-scoped facts written before this change carry `agent_id = config.agent.name` (default `Sinty`). They stay
  visible to sessions outside projects and to a persona whose roster id equals that name; other personas no longer
  see them. Move them with SQL if needed: `UPDATE memory_facts SET agent_id = '<persona>' WHERE agent_id = 'Sinty'`.
- If `plugins.enabled` in a user's `config.yaml` still lists `memory`, start reports `plugin memory failed to
  start` (not found). Remove it from the list; the core memory is always on.

## Known limitations

- The duplicate-tool warning is a log line only; it is not shown in the UI.
- Facts with equal `created_at` (same millisecond) may be ordered differently than the old SQL `ORDER BY`; the
  golden tests did not observe a difference.
