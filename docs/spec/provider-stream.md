# Provider stream acceptance and diagnostics

Strict Zod chunk envelopes reject unknown/partial fields and non-finite token usage. Exact wire-to-canonical names come from the advertised registry, not string guessing; child allow-lists compare canonical identities.

The SDK ProviderChunk contract is provisional until exactly one terminal done, normal iterator completion and a non-aborted signal. The core buffers a whole attempt and accepts its complete call batch **before** model.response or tool.call.requested. A failed attempt creates neither executable event; existing fallback selection remains unchanged. There are no new retries or automatic repair loops.

## Wire contracts

- Chat Completions (openai-compat): one choice (index 0; an omitted choice index is accepted only for a singleton legacy choice), explicit nonnegative tool indices, stable nonempty ID per index and unique IDs. Name and argument fields are deltas by default. Require finish_reason plus [DONE]; calls require tool_calls, not length/content_filter/stop. Usage-only chunks between finish and [DONE] are allowed.
- Some gateways repeat a **complete name as metadata**, not a delta. Only explicit endpoint options.toolCallNameMode: metadata enables that contract. Repeated names must agree exactly. Arguments remain deltas. The default delta mode preserves legitimate fragmented names, including equal adjacent fragments. It never removes repeated substrings or guesses an unknown tool. An unexpected repeated full name fails catalog validation. No gateway, including RH, is automatically classified from its hostname or model name; no user configuration is migrated.
- Native Anthropic: names are block-start metadata; only input_json_delta appends arguments. Block indices cannot be reused or closed twice. Calls stay buffered through message_stop, a complete block lifecycle and stop_reason=tool_use. A nonempty initial input and later JSON deltas conflict. EOF, errors, abort or max_tokens with calls cannot expose calls.
- Responses: output_item.done.arguments is one full snapshot, never a delta. Output index, item ID and call ID must be unique; added/progress/done metadata cannot change their correlation. All calls wait for response.completed; when its output snapshot is present it must agree. EOF/failed/incomplete with calls fail closed. Text-only incomplete may retain its length/incomplete terminal reason, without any tool call.

Across adapters and core: max 128 calls, IDs/names 1..256 characters, argument strings at most 1048576 characters. Arguments must be complete finite JSON objects, validated against the exact advertised wire ToolSchema. No invalid-JSON sentinel, fallback ID, fuzzy name or partial call execution. The legacy root __invalid_json argument key is reserved and rejected. Unsupported argument schemas fail closed, not permissively. The SDK uses Ajv plus standard ajv-formats for exact JSON Schema validation: the existing experimental Zod converter was measured accepting absent required fields/default annotations, so it is not a safe boundary validator. This is the only new transitive runtime dependency of core, located in the shared SDK. Draft-07, 2019-09 and 2020-12 are supported; absent dialect defaults to 2020-12, with legacy array-form items selecting draft-07. Unknown keywords, unresolved/external references and async schemas fail closed. There is no remote schema loading, default insertion, coercion or removal of properties. Validated data is not replaced by validator output. Plugin execution-time Zod validation remains authoritative for plugin refinements.

Core IDs cannot repeat an earlier accepted response in the turn or retained request history. The entire batch is rejected before journaling executable calls if one entry is invalid. Recovered old pending batches are checked before parallel dispatch, and calls are checked again at actual execution. Empty/duplicate historical IDs fail the turn once, rather than emitting unresolvable per-call failures forever. Legacy partial responses, truncated stop reasons and invalid-JSON sentinels cannot dispatch. Current catalog, allowed-tool subset, plugin visibility and deny policy/path revocations are checked at dispatch, including previously approved calls. Existing approval and generation-fencing logic remains in force. This does not undo effects of historical already-executed tools.

## Safe opt-in diagnostics

Set options.streamDiagnostics: true on a provider endpoint **only when needed**. Local-only options are stripped before sending the HTTP body; nothing enables this in existing user configuration. On protocol errors only, bounded version-1 metadata is attached to the error hint: frame count, terminal flag, choice 0, and at most 16 rows containing numeric tool index, ID/name/argument lengths and row-update/repeated-metadata counts. No raw names, IDs, arguments, prompts, responses, reasoning, URLs, headers, API keys or original stream-error payloads are recorded. Counters cap at 1000000. No raw SSE recording is added.

The core writes opt-in model.stream_error { attempt, code: provider_protocol_error, diagnostics? }, correlated by the existing sessionId/turnId/stepId and preceding model.request. It strictly parses the numeric/boolean metadata schema (hint <=4096 characters); arbitrary provider hints are not journaled in this diagnostic event. This preserves safe per-attempt diagnostics even when a fallback succeeds. Default operation adds no diagnostic event. Human-readable protocol errors use fixed reason codes, not model-provided names or JSON parser snippets.

## Regression verification

Run pnpm install --frozen-lockfile, pnpm typecheck, then pnpm test:p0 (also included at the end of pnpm test). tests/provider-stream.test.mjs imports the real compiled adapters, SDK validators and Agent methods. All HTTP is mocked, unmocked fetch throws, and tools never dispatch. Fixtures cover healthy DeepSeek-style deltas, fragmented/equal name fragments, explicit repeated metadata, interleaving and identity collisions, snapshots, malformed JSON/schema/catalog, missing/truncated terminals, abort/errors, multiple choices, duplicate Responses events, native block lifecycle, attempt isolation, pre-journal gating and current permission revocations.

The historical RH SSE frames were unavailable during the audit. The reproduced name-concatenation mechanism is established; a gateway's actual historical frame contents are not. These P0 changes deliberately exclude retry/backoff, watchdog changes, memory/summary/cache, dynamic discovery, output budgets, UI and autonomy redesign. No installation or restart is part of the PR.

Compiled JSON Schema validators have a bounded in-memory LRU (64 entries, 1048576 schema characters total, at most 131072 per entry), keyed by exact JSON bytes and compiled from a private snapshot. This prevents repeated compilation from serializing parallel tool dispatch; it caches no arguments, results, tool availability or permission decisions and does not change provider prompt caching. Schema edits/mutations select a new validator; permissions remain fresh.
