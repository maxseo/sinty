# Office Docs (zero-dependency)

Движок живёт в `tools/office/office.cjs` (один файл, только встроенные модули Node: `fs`, `path`, `zlib`).
Никакого npm: в песочнице нет сети и `npm` не запускается.

## Почему job.json

Песочница запускает скрипт как eval и **вырезает аргументы командной строки**
(`process.argv` = `["node-real.exe","-"]`). Поэтому параметры передаются файлом `tools/office/job.json`.

## Запуск

1. Записать задание в `tools/office/job.json`.
2. `node tools/office/run.cjs`

### Формат задания

```json
{ "cmd": "docx", "file": "_inbox/doc.docx", "out": "_work/doc.md" }
```

| `cmd` | Поля | Что делает |
|---|---|---|
| `ls` | `file`, `out?` | список частей zip-контейнера |
| `docx` | `file`, `out?`, `json?` | markdown: заголовки, параграфы, списки, таблицы |
| `xlsx` | `file`, `sheet?` (с 1), `limit?`, `out?` | дамп листов: значения и формулы |
| `pdf` | `file`, `out?` | текстовый слой + диагностика (шифр, CID, скан) |
| `build` | `spec` (inline), `outFile` | собрать xlsx из спецификации |

### Спецификация xlsx

```json
{
  "sheets": [{
    "name": "Требования",
    "cols": [6, 40, 60, 14],
    "freeze": { "row": 2, "col": 0 },
    "autoFilter": "A2:D50",
    "merges": ["A1:D1"],
    "rows": [{ "cells": [{ "v": "Заголовок", "s": "title" }] }]
  }]
}
```

Ячейка: `{ v, f, s, cached }` — значение, формула **без** ведущего `=`, стиль, кэш формулы.
Стили: `title`, `header`, `text`, `num`, `formula`, `bold`, `section`, `note`, `default`.

Формулы пишутся живые, кэш (`cached`/`v`) нужен, чтобы Excel показал число до пересчёта.

## Ограничения (честно)

- docx: текст, заголовки, списки, таблицы, картинки как `[image]`; колонтитулы и сноски не читаются.
- xlsx: значения, формулы, merge, ширины, заморозка; **не** читаются conditional formatting, диаграммы, картинки, стили не переносятся один-в-один.
- pdf: только текстовый слой. Скан без слоя → нужен OCR. CID-шрифты без ToUnicode → текст нечитаем.
- `.xls` (старый бинарный) и `.doc` (не OOXML) не поддерживаются: сначала пересохранить в новом формате.

## Подводные камни, пойманные на живых файлах

- **Релсы OOXML**: атрибуты `Relationship` идут в любом порядке (`Type, Target, Id`),
  поэтому `Id` и `Target` надо вытаскивать по отдельности, а не одной регуляркой по порядку.
- **Стили не переносятся сами**: у исходника свои индексы `s="N"`; нужна таблица
  `индекс -> имя стиля`, иначе оформление теряется.
- **Диапазоны в формулах надо пересчитывать** после изменения числа строк:
  `SUM(E6:E43)` не станет `SUM(E6:E55)` само.
- **Двуязычные docx**: в `source` текст разложен по ячейкам, в `publication` — обе версии
  в одной ячейке подряд. Фильтровать кириллицей, иначе требования дублируются.

## Правило проверки

После сборки xlsx всегда читать его обратно (`cmd: "xlsx"`) и сверять: число строк, наличие формул, merge.
Дополнительно сверять множества: что было в источнике и чего нет в результате (потери)
и наоборот (фантомы). Проверять нумерацию на разрывы — пропуск пункта виден сразу.
